# template_sia

Public exemplar for the SIA (Self-Improvement Agent) harness: Meta → Target → Feedback
loops with public/private task splits and canonical generation artifacts.

## When to use this template

Use this template when you need a **self-improvement-agent evaluation
harness**: Meta → Target → Feedback generation loops, public/private task
splits to detect overfitting, deterministic fixture replay for testability,
and fail-closed loop validation. Its opt-in local Ollama lane proposes one
numeric classifier parameter, evaluates the resulting source in Docker, and
records sandbox selection and exact rollback. For
agent-team coordination mechanisms see
[`template_autoscientists`](../template_autoscientists/); for a bounded
AutoResearch loop see
[`template_autoresearch_project`](../template_autoresearch_project/). Full
roster:
[`projects/AGENTS.md`](../../AGENTS.md#permanent-canonical-exemplars).

## Quick start

```bash
uv run python projects/templates/template_sia/scripts/run_sia_loop.py
uv run python projects/templates/template_sia/scripts/z_generate_manuscript_variables.py
uv run python scripts/pipeline/stage_01_test.py --project templates/template_sia --project-only
```

Default runs replay fixtures under `src/template_sia/fixtures/recorded_generations/`.
`--live-sia` remains a bounded diagnostic run of unchanged reference code.
The reusable Layer-2 adapter is `src/template_sia/loop/loop.py`; `scripts/run_sia_loop.py` is a
thin CLI that parses flags, calls that adapter, and prints artifact paths.

## Bounded live numeric proposals

Select an already available local Ollama model and an immutable local Docker
Python image ID, then use a fresh output directory:

```bash
uv run python projects/templates/template_sia/scripts/run_sia_loop.py \
  --live-proposals --model <local-model-name> \
  --container-image sha256:<existing-local-image-id> \
  --proposal-output-dir projects/templates/template_sia/output/live_proposals_example
```

The model returns a finite threshold and short rationale. The controller changes
only the fixed reference code's `THRESHOLD` literal. At most three generations
run, each target has a 60-second deadline, and each model request has a total
60-second deadline. Docker uses no network, a read-only root, three scoped
mounts, no host credentials, and CPU, memory, and process limits. The model
sees the fixed public selection cases; the frozen synthetic holdout is scored
once after selection and never enters its prompts.

Each run retains actual model request/response and execution diagnostics,
container execution receipts, predictions, exact proposal diffs, rollback
source bytes, and pending approval receipts. Source application requires owner
approval and is unsupported by this command. Missing Docker, a pinned local
image, or the selected model returns blocked exit 75; a failed proposal or
evaluation returns nonzero and retains its receipt. No automatic download or
host execution fallback supplies live acceptance.

The toy fixture thresholds already score 1.0. A real numeric mutation can be
rejected for failing to improve that score; a successful run demonstrates
bounded proposal/evaluation/rollback behavior, with its measured scores.
It establishes no general self-improvement claim. Controlled HTTP test fixtures
verify API custody and Docker behavior; actual Ollama acceptance requires a
separate run against the selected local model.
