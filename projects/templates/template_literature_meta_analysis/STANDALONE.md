# Standalone Fork Guide

The intended 0.2.0 package pins `research-project-template` in `pyproject.toml`
for its shared validator and platform adapters. The checkout's
`tool.uv.sources` entry resolves that dependency to the public monorepo. An
independent source checkout installs an explicitly built platform wheel matching
`pyproject.toml` and
this project's `dev` extra using pip as shown below; pip does not consult that
checkout-only resolver. Installed-wheel acceptance separately installs both actual
wheels outside the checkout. These are unreleased candidates, so do not assume
they exist on PyPI. Core validator imports must work from the installed distributions.

## Purpose

`template_literature_meta_analysis` is the canonical **literature meta-analysis**
exemplar: multi-engine retrieval with graceful degradation, record de-duplication,
full-text resolution, descriptive statistics, language/entity analysis, document
embeddings, citation and temporal bibliometrics, an optional knowledge-graph layer,
and an auto-injected manuscript. Default allowlisted analysis consumes the
synthetic fixture offline after dependency preparation (bundled term:
**modafinil**); explicit retrieval/enrichment commands have their own network
and provider prerequisites.

## Copy This When

Use it whenever the research object is *a body of literature about a topic*: point
one config key at a search term and get a reproducible, evidence-traceable
meta-analysis whose every manuscript number is computed from committed artifacts.

## Clean Copy Command

From the template repository root:

```bash
uv run python scripts/audit/copy_exemplar.py \
  --source templates/template_literature_meta_analysis \
  --dest projects/working/my_meta_analysis \
  --new-name my_meta_analysis
```

Fallback when the helper is unavailable:

```bash
rsync -a \
  --exclude '.venv/' --exclude '.pytest_cache/' --exclude '.ruff_cache/' \
  --exclude 'htmlcov/' --exclude 'output/' --exclude 'rendered/' --exclude '*.egg-info/' \
  projects/templates/template_literature_meta_analysis/ projects/working/my_meta_analysis/
```

## Required Post-Fork Edits

- Set the topic in `manuscript/config.yaml` → `project_config.search.term` and the
  `query` / `arxiv_queries` / `relevance_keywords` / `subfield_keywords` /
  `hypothesis_definitions` blocks for the new domain.
- Update `CITATION.cff`, `.zenodo.json`, `codemeta.json`, and `pyproject.toml`
  (title, keywords, repository).
- For a new fork's offline seed corpus, first prepare its actual SDK/dev
  environment below, then run from that project root:
  `.venv/bin/python scripts/generate_fixture_corpus.py --term <your_term>`.
  Do not overwrite an actual live corpus to satisfy an onboarding step.
- Script `01_literature_search.py` is an explicit network retrieval command,
  not the offline starter. Configure engine toggles and each provider's
  eligibility, credentials or contact identity before invoking it; enabled
  keyless engines can still make network requests. Engine-specific failures and
  skipped states are recorded in `output/data/retrieval_report.json`.
- Default allowlisted analysis consumes fixture/current corpus data without
  launching script `01`. Resuming a populated `output/data/corpus.jsonl` can
  skip new network searches; retain actual retrieval provenance before
  claiming freshness or empirical findings. See the
  [existing stage commands](scripts/README.md#stage-commands).

## Validation Commands

From the template repository root after copying into `projects/working/`:

```bash
uv run python scripts/pipeline/stage_01_test.py --project working/my_meta_analysis --project-only
uv run python projects/working/my_meta_analysis/scripts/generate_fixture_corpus.py
```

For the public exemplar:

```bash
uv run python scripts/pipeline/stage_01_test.py --project templates/template_literature_meta_analysis --project-only
```

For an independent source checkout, create its own environment from its root
(using a supported Python 3.14/3.15 interpreter), install the explicitly built
platform candidate wheel, and install this project's declared runtime/dev
requirements. Replace the wheel path with the actual reviewed artifact:

```bash
python3.14 -m venv .venv
. .venv/bin/activate
python -m pip install /absolute/path/to/research_project_template-5.2.0-py3-none-any.whl
python -m pip install '.[dev]'
python -IB -m pytest tests/ --cov=src --cov-fail-under=90
```

Pip uses the declared package dependency rather than the checkout-only
`tool.uv.sources` resolver. No monorepo `scripts/pipeline/` path is required. Isolated Python prevents the
checkout working directory from becoming an ambient SDK import provider; the
conftest binds the declared SDK before registering own source.
The configured test suite exercises source registered by its own conftest;
installed-wheel execution and exact-revision acceptance remain separate gates.
The candidate platform SDK must be supplied explicitly at the declared version until it is
actually published. Installing dependencies requires package access; ordinary
corpus analysis and the default tests use deterministic fixtures or local servers.

## Determinism & Offline Default

The committed `data/fixtures/<term>_corpus.jsonl` is **synthetic** (reserved
`10.5555/` test DOIs, generated authors). After dependency preparation, the
default analysis allowlist consumes fixture/current corpus data without
launching live script `01`; it does not promise that every script is network
free or that every failure becomes `skipped`.

Live retrieval is separately authorized and provider-prepared, including any
enabled keyless engines. A populated resumed corpus can avoid new requests, so
its existence alone does not prove retrieval freshness. Real bibliometric
claims require actual retained retrieval provenance, regenerated analysis and
independent domain assessment, not relabeled fixture or resumed output.

## What Not To Claim

Do not present the synthetic-fixture numbers as empirical findings about the topic.
They demonstrate the machinery; real claims require a live retrieval run plus
regenerated figures, reports, and manuscript variables.
