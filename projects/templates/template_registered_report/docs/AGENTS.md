# AGENTS.md — docs/ for template_registered_report

Agent-facing notes for this documentation tree. The nearest authoritative
contract is [`../AGENTS.md`](../AGENTS.md); monorepo-wide rules live in
[`../../../../AGENTS.md`](../../../../AGENTS.md). Decision-memory and
verifier-hardening rules follow the monorepo
`docs/rules/memory_and_decision_records.md`.

## Layout

- `src/registered_report/` — preregistration schema, protocol validation,
  registered analysis, deviation ledger, and figure-data logic. See
  `src/AGENTS.md` and `src/README.md`.
- `scripts/` — thin orchestrators only; business logic belongs in `src/`.
- `tests/` — zero-mock suite (`test_protocol.py`, `test_demo_study.py`,
  `test_figures.py`, and script tests for both orchestrators).
- `manuscript/` — `manuscript/AGENTS.md` (if present) plus section README
  govern that tree's token/figure/bibliography rules.

## Conventions observed in this repo

- Every quantity reported in the manuscript is produced by the tested code in
  `src/registered_report/` and regenerated by `scripts/generate_figures.py`;
  none is hand-entered or illustrative (`manuscript/00_abstract.md`).
- Confirmatory versus exploratory claim boundaries are explicit; deviations
  go through the deviation ledger, never silent prose changes.
- Keep volatile counts generated, not transcribed into prose.
- Never hand-edit `output/`; regenerate through the pipeline.

## How docs here are maintained

- Keep this tree short and factual; one file per concern.
- Measured counts belong in the monorepo's generated
  `docs/_generated/COUNTS.md`, not here.
