# 5.1.0 — reviewable publication evidence

5.1.0 coordinates the Root SDK and the canonical public exemplars. This note
describes Source changes and the release controls they require. The matching tag,
exact-source acceptance artifacts and authenticated publication records establish
the release outcome; a version number, note or illustration cannot establish it.

## What changes

- ARL capability readers share one invocation's actual original producer and
  consumed/model commitments. The first verdict is retained even on failure;
  projections reuse that audited original rather than running the producer again.
- An exclusive downloaded-original ARL readback mode authenticates the same
  Source/run/attempt, retains and imports its immutable carrier into a fresh
  destination, then invokes the existing full reader independently. It starts
  no provider or model producer and grants no aggregate acceptance.
- Downloaded auxiliary evidence is imported one member at a time under the
  existing native aggregate budget. Per-file, member-count, capacity, deadline,
  path, type and integrity checks remain enforced; the complete evidence closure
  is retained rather than trimming required bindings to fit a smaller decoder.
- A manual four-target Root census workflow collects actual family observations
  and reviews an exhaustive classification template in the same checkout and
  runtime. It gives no family a default classification, does not automatically
  install its authored DATA, and cannot establish runtime or release acceptance.
- A separate four-target tagged-PDF probe runs the existing real rendering test.
  Its strict one-case result requires a pass with no skip; tool installation
  alone cannot establish that the required PDF tagging capability works.
- Literature HTTP error attempts retain bounded observations from five
  allowlisted response headers, distinguishing absent from unavailable and
  omitting unsafe or ambiguous values. Existing retry behavior is preserved;
  these observations are not a provider-quota determination.
- Rendered-publication refusals retain structured validation-input differences
  and Source descriptors, making a stale report distinguishable from a different
  checkout. Original worker exits and diagnostic streams remain evidence.
- The Active Inference producers prepare native transmission images before
  hydration audits. Bounded phase observations retain process and output facts
  without treating a quiet interval or a log line as producer completion.
- Newspaper image components keep the readable fallback for missing or corrupt
  images while allowing resource refusals and unexpected programming errors to
  propagate. Real valid-image, corrupt-image and resource-limit controls run in
  its persistent CI smoke selection.
- Development and scientific dependency updates retain their project lock
  boundaries. Ordinary CI qualifies its actual selected consumers; it does not
  replace the full native, installed, process or release acceptance lanes.
- Artifact-only refresh and rebind review paths retain candidate patches,
  changed-blob manifests, original exits and committed-tree gate receipts.
  Reviewed pull requests integrate those bytes; the inactive direct-push lane
  remains subject to its separate credential and branch-protection decision.

- The coordinated publication workflow runs all six phases in one invocation
  under the existing fresh unprivileged Linux execution account. Original
  process supervision and census refusals remain enforced. Generation uses
  exactly one worker because concurrent projects under that shared account can
  interfere with each other's final census; unsafe worker counts refuse before
  any phase or producer. Verified review artifacts are retained only after every
  phase succeeds.
- Linux document preparation selects one frozen official TeX Live 2025 final
  distribution. Pinned installer and repository database bytes keep engines and
  packages coherent, while the tagged-PDF test retains its actual pass and
  no-skip requirements.
- Native matrix producers pack their exact single selected original; complete
  acceptance and release handoff explicitly collect all 25 real cell custodians
  under one Source owner and deadline. Receipt, provider and transport paths
  are distinct at original creation. The reader consumes the original receipt
  bindings and retains the full-union admission requirement.

- Multi-project resume reaches the existing checkpoint policy; missing, stale
  or non-reusable checkpoints retain their refusal rather than starting fresh
  work. Unsupported all-project incremental requests fail before execution.
- Optional PDF processors snapshot validated configuration and keep document
  identity and hashes local to each call. PDFs and selected sidecars are staged
  and validated before publication. Destination modes are preserved, new files
  use atomic no-clobber publication, and ordinary failures recover only the
  invocation's own replacements. These are per-file visibility and recovery
  controls, not a crash-atomic transaction across multiple files.
- PDF catalog objects survive overlays, metadata injection and encryption
  unless the caller explicitly replaces metadata. Password encryption keeps
  embedded provenance attachments; encryption nonces retain fresh randomness.
- Optional Kmyth handling preserves inputs and existing sidecars until a
  validated replacement is ready, refuses aliases and scrubs inherited
  credential names and agent sockets. This Source change does not establish a
  live TPM sealing result or change the vendored upstream commit.
- The CORS helper omits the allow-origin header when no origin is allowed.
  Shared pipeline examples use the actual public methods, and successful native
  cell artifacts receive the same 30-day retention as the other retained lanes.

- A new exact Mermaid CLI 12.2.0 profile uses the patched Mermaid 12.3.0 browser
  distribution, with embedded KaTeX 0.18.11. Its separately resolved KaTeX
  package is 0.18.10; both satisfy the upstream advisory
  [GHSA-238p-pmpm-9mq7](https://github.com/advisories/GHSA-238p-pmpm-9mq7).
  The Source profile retains the SDK font constructor, used-face embedding,
  1400 by 900 native viewport and scale 1, with upstream embedding explicitly
  disabled. Standalone custom dimensions retain a distinct request contract.
- The locked Puppeteer 25.16.0 chain resolves Zod 4.6.7, addressing
  [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).
  Scoped npm audit and real output-only inherited-trust controls accompany the
  dependency update. These observations do not establish application-wide
  security or replace actual browser/native qualification.
- Documentation setup selects the headless browser through its actual locked
  Puppeteer package. Mermaid caches bind the rendering profile and relevant
  source, font and toolchain inputs; an active native custody frame still
  requires every original renderer call. Historical 11.16.0 and 12.0.0 profiles
  retain their own declared boundaries.
- Image sources are rebased only in emitted HTML, before exact figure-registry
  matching. Raw Markdown code retains literal paths and image tags, including
  inline and fenced examples.
- Compiler citation requests, including `nocite` and included auxiliary files,
  require a successful native BibTeX exit. Unused bibliography files do not
  force processing. Failure aborts before final PDF promotion.
- Direct PDF renderer failures preserve the prior final PDF and cannot reuse an
  old final or staging file as a new successful render. Stage 03 still performs
  its strict pre-run cleanup; the whole pipeline is not a transactional
  replacement of a prior publication.
- Explicit generated-ordering manifests bind the renderer's actual ordered
  inputs and consumed configuration with truthful null authored-source fields.
  Invalid declarations fail; compiler freshness and scientific provenance remain
  the project's separate responsibility.
- Output-validation public providers resolve lazily. Cold evidence-registry and
  rendered-snapshot readers do not require pre-importing unrelated checks;
  existing validation rules and public provider identities remain unchanged.
- Stage 03 preserves the selected HTML asset mode. An explicit local request
  publishes the Source-pinned MathJax loader and font closure, or refuses
  missing/invalid prerequisites and unconfinable destinations instead of
  silently emitting CDN references.
- Browser math discovery appends scanner entries individually instead of
  spreading every prose run into a function argument list. Large books retain
  raw and Pandoc mathematics, selected roots, ignore/process boundaries, source
  positions and live viewport reflow. The Source-owned find action mirrors the
  pinned MathJax 4.0.0 mapping; review that integration when upgrading MathJax.
- Document roots stay unclipped so deep mobile anchor navigation does not blank
  long-book content. Existing responsive wrapping and table-local scrolling
  remain responsible for horizontal layout rather than hiding page overflow.
- Stage 04 content and evidence readers inspect that same generated roster,
  including deep files, rather than neutral templates or unselected residue.
  Existing optional diagnostic and severity policies remain unchanged.
- Rendering-package exports resolve lazily, matching the existing core/validation
  facade convention. Shared discovery and bibliography readers no longer
  initialize unrelated format providers during validation.
- Core's existing lazy facade exports are visible to API discovery without
  initializing heavy providers or changing their runtime identities.
- Linux hardening stays on the reviewed Noble runner. Active's existing
  dependency group is installed in the interpreter that actually runs its
  tests. Cold preparation builds exact locked runtime sdists with Source-locked
  backends; actual selected-minor nomination and fresh offline, no-build,
  exact-hash consumers remain enforced.
- Original pytest worker identity comes from actual pytest configuration, not
  an inherited worker environment in a fresh serial controller.
- Native stream observations have an explicit schema and remain distinct from
  confined artifact bindings. Disposable source copies retain independent bytes
  without propagating privileged BSD file flags.
- The local font transport preserves native unknown-size LZMA streams. Its
  synchronous decoder requires an exact finite output budget, bounds input and
  dictionary, and rejects incomplete, over-budget or trailing data. Every
  original font body, hash and full license is retained.
- Python-floor checks reject lazy imports unsupported by the declared floor;
  fresh distribution identity permits missing optional Version metadata.
  Bytecode consumers use the current module specification.
- Prose editorial counts and readability remain derived measurements, not fixed
  wording baselines. Current bibliography resolution and native consumer
  integrity controls remain enforced; incidental wiring assertions are retired.
- Native CLI, receipt and progress output retain their machine-readable
  stdout/stderr channels, newlines, explicit flushes and original exits without
  library `print` calls.
- Regression selection requires every declared populated test file to
  contribute cases, rather than an incidental suite-size floor. Empty fixture
  packages and non-collected scaffolds no longer claim regression coverage.
- Markdown reference validation recognizes Pandoc IDs alongside class and
  quoted key-value attributes; quoted hash text cannot define a missing target.

## Coordinated metadata

The Source-owned minor transaction moves `5.0.2 → 5.1.0`. Its exact reviewed
canonical plan SHA-256 is
`148607b9b5e69d0536df96b7b15fe177575da8b7c83cc3c197cdb61aa1a3306d`.

The transaction changes 77 files: Root metadata and lock, plus each of the 25
canonical exemplars' SDK requirement, compatibility binding, local editable SDK
lock record and manuscript publication platform binding. Every exemplar keeps
its own package version, intended/publication versions, provider declarations
and third-party dependency records. Exact original bytes remain in the private
transaction journal. Planning and applying this delta performs no dependency
resolution, installation, tag creation or publication.

The local editable SDK records refer to the selected Root Source, so metadata
preparation does not require a pre-existing 5.1.0 package on an index. Installed
5.1.0 behavior must still be established from genuine built artifacts in the
required lanes; editing installed distribution metadata is not a substitute.

## Final Source, outputs and coverage

Freeze the final implementation, dependency locks, version bindings and authored
release materials before generating release evidence. In Source provider order,
the default workflow refreshes the fifteen tracked publication-copy projects and
runs canonical Stage 02 analysis followed by the normal refresh for Pitch, the
separately declared counts consumer. It revalidates unchanged output bytes for
the nine-project complement. The plan derives the publication-copy roster from
tracked Source rather than maintaining another fixed project list.

After genuine coverage measurement at committed Source `C`, import the measured
literals and their provenance while `HEAD` is still `C`, then commit that import
as `D`. Refresh publication outputs that consume the imported measurements through
their real producers. Pitch concretely reads `COUNTS.md` for coverage charts and
PDF/PPTX deck content, so its displayed values must be regenerated when those
inputs change. An unchanged raw output fingerprint alone cannot establish that
the displayed measurements are current.

Review and commit the dependent generated delta as `Q` (`Q = D` only when no
dependent output changes are required). Compare all 25 project source hashes and
the Active Inference support hash against the actual measurement at `C`. Preserve
that measured identity only where those inputs still agree; remeasure affected
source changes rather than relabeling percentages.

Dispatch the coordinated publication workflow at branch `Q` in explicit
`rebind-only` mode: all 25 original Stage 4 rebind calls must preserve their
output fingerprints, with no render or analysis fallback. Review the generated
report-only patch as `E`. Any additional fingerprint refusal requires its real
refresh and another input-hash comparison; never restamp changed bytes.

Candidate outputs must pass the unchanged all-project exemplar-config guard and
both strict publication audits on their committed tree. Preserve all original
exit results and receipts. Those checks are necessary preparation for acceptance.

## Release requirements and historical custody

The release ceremony requires a genuine Linux CI Gate, reviewed integration and
tree comparison, followed by the complete exact-main required-acceptance run,
authenticated indexed artifacts, installed handoff and release-workflow
verification described in the [release boundary](../maintenance/release-boundary.md).
Partial CI, a metadata check or this illustration cannot authorize a release.

As of the 2026-11-05 metadata preparation, final 5.1.0 Source, policy classification,
publication regeneration, coverage measurement and exact-main acceptance were
still being coordinated. That dated preparation status is historical context;
the authenticated records at the eventual release revision decide its outcome.

Preserve `v5.0.0`, `v5.0.1` and `v5.0.2` exactly where they are. In particular,
the retained `v5.0.2` tag receives no retroactive GitHub Release. Historical notes,
artwork, failed runs and original receipts remain records of their own revisions.
