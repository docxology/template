# Research Project Template 4.0.1

![Template 4.0.1 repository and update overview: configure, test, analyze, render, validate and publish; a shared Python SDK, 25 public exemplars, source and runtime identity, native witnesses, portable artifacts and exact release bytes.](https://github.com/docxology/template/releases/download/v4.0.1/template-v4.0.1-overview.png)

`template/` is an open-source platform for reproducible research. A shared Python
SDK supports 25 independently versioned public projects. The pipeline connects
configuration, tests and analysis to PDF, HTML, DOCX, EPUB and slide deliverables.
Python 3.12, 3.13 and 3.14 remain the supported runtime matrix.

This is the requested 4.0.1 candidate following preparation of 4.0.0. The 4.0.0
candidate was not published; the preceding published root release is v3.8.0.

## Candidate fixes

- Bind platform metadata, public project declarations, exact SDK requirements,
  installed/export admission and lock identities to 4.0.1 while preserving every
  project's independent version and historical DOI/deposit records.
- Preserve source-relative section identities when manuscript filenames repeat
  across chapters, and require one exact consumed source selection.
- Bind original native processes to their actual operating-system PID and
  independently observed supervisor/worker host. Authenticated hosted evidence
  requires the declared Linux producer; timeout and interruption outcomes retain
  their original exit codes.
- Keep authored SDK members, installed-wheel bytes, source distribution bytes,
  release image and retrieved publication assets bound to the accepted source.
  The release workflow selects the notes and image for its actual release tag.
- Retain bounded source/native/portable checks, genuine positive and negative
  controls, exact dependency/tool/font custody and complete publication gates.
  Source-specific PDF, HTML, Office, print and projection adapters remain subject
  to their complete acceptance requirements.

## Publication boundary

update. They do not assert that the remaining local, hosted, native, installed,
export, transfer or publication gates have passed. Release publication requires
fresh final-source acceptance and the exact authenticated hosted artifact.

and `template-v4.0.1-artifacts.json`. The final release body must identify the
accepted commit, hosted run/artifact and aggregate receipt hash. Each public
