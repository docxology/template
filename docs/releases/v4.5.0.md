# Research Project Template 4.5.0

4.5.0 is the current minor release candidate. It incorporates the unpublished
4.4.1 preparation and its follow-up corrections. Root metadata, all 25 canonical
exemplar SDK requirements, lock roots, and manuscript platform bindings move
together. Exemplar package and publication versions remain independently owned.

![Template 4.5.0 release contract: current interfaces, guarded native execution, bounded CI, standalone exemplars, and exact-source acceptance.](template-v4.5.0-overview.png)

The [editable diagram](template-v4.5.0-overview.svg) describes the contract,
not completed acceptance or publication.

## One current interface per responsibility

- Agent discovery uses `.agents/` and version-2 skill manifests with `agent_ref`.
- Security uses `SecurityViolation`; lexical test-policy checks use the structured
  `scan_lexical_mock_policy` result. Rendering uses its canonical CLI.
- Output validation requires explicit `enabled_formats`; PDF requirements follow
  the selected formats. Artifact manifests declare their inventory mode.
- Search caches include schema and query identity. Backlog entries include status
  and next action. Hydration removes only unchanged previously owned outputs.
- AutoResearch uses one review-packet builder and validator. Readiness never
  substitutes for human publication approval.
- Installed render and validation entrypoints resolve the source checkout rather
  than treating the installed SDK directory as the exemplar workspace.
- Code analysis and Experiment Tree hydration require their declared SDK; missing
  or broken imports fail rather than report degraded success. Code analysis
  completion requires a persisted validation report. Standalone mathematical
  primitives and explicitly selected draft generation remain independent.

The detailed interface migration is retained in the
[superseded preparation notes](v4.4.1.md). Historical notes are not current usage
instructions and are not evidence of publication.

## Bounded execution without weaker validation

Native synchronous command construction groups data checks inside opening and
closing source guards. Restored-file mutations must still fail the closing
guard. Process boundaries, tool identity, original exits, and deadlines remain
independent controls; reduced source scanning is not itself runtime acceptance.

CI preserves complete contract modules and their original serial result streams
while distributing independent jobs. Guide-only selection retains documentation
contracts without scheduling unrelated exemplar execution. Native bootstrap
ownership includes direct caller tests. Ubuntu preparation validates supported
regional mirrors without relaxing signed repository or file-custody policy.

## Core and standalone delivery

The root package and canonical exemplar sources are the coordinated source of
truth. Standalone public `template_` repositories receive reviewed exports only
after their required source and package checks. A source update does not prove
that a standalone repository, its default branch, or a published package changed.

Required acceptance covers the source-owned obligations, the root plus all 25
exemplars on both supported Python minors, and applicable native execution.
Publication audits retain per-project reports and original process exits;
passing JSON cannot override a failed child process.

Follow the [release boundary](../maintenance/release-boundary.md): freeze the
final source, pass exact-revision hosted acceptance, authenticate its complete
artifact collection and aggregate receipt, then create the matching unused tag
and invoke the release workflow. Verify downloaded release assets independently.

## Acceptance status

No 4.5.0 release is claimed by these source changes. Existing tags, original
receipts, and unique local work remain preserved. Remove obsolete active
