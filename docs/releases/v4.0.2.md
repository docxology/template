# Research Project Template 4.0.2

![Template 4.0.2: focused CI and isolated contract tests feed cold native preflight, complete exact-source acceptance, and a verified release handoff.](https://github.com/docxology/template/releases/download/v4.0.2/template-v4.0.2-overview.png)

**Release intent: 2026-10-15.** Publication requires the successful exact-revision
acceptance and authenticated handoff described in the [release boundary](../maintenance/release-boundary.md).
The earlier 4.0.0 and 4.0.1 preparations were not published. This release includes
that prepared Platform 4 work and the feedback and qualification improvements below.
Each public exemplar retains its independent package version and historical publications.

## Faster, accountable feedback

- Split the complete infrastructure smoke roster into complementary shards.
  Include changed tests and declared Source owners, with expensive full modules
  in a separate required contract lane. CI checks original pytest member and
  outcome receipts across both lanes and refuses missing or overlapping selections.
- Narrow project-only pull requests using declared transitive dependencies.
  Shared, unknown, renamed or deleted inputs conservatively select the complete
  public roster; main and manual runs retain complete functional project selection.
- Retain JUnit timings and strengthen serial/parallel benchmarking with independent
  cold and warm worktrees, exact member/outcome parity and both speed comparisons.
- Bind download caches to the resolved interpreter, platform, dependency group,
  lock and package metadata. Locked reconciliation remains mandatory.
- Measure full own-project coverage across the Source-derived public roster in
  one manual dispatch, with four concurrent projects and separate original
  measurement artifacts. CI's optional single-project coverage uses the same job.

## Earlier failures and less repeated work

- Add an installed native diagnostic preflight with a bounded original clock.
  It prepares the complete provider roster, checks boundary providers and executes
  one genuine exemplar through Original and independent Current analysis.
  Its incomplete diagnostic receipt cannot authorize publication.
- Revalidate fixed native runtime and Current nomination batches inside every
  existing use window. Retain each member's physical, wheel, installed-file,
  audit, native-image, process and deadline checks, including selected-member
  closing observations. Standalone later-use guards remain enforced.
- Run Linux auxiliary qualification alongside common installed/runtime work.
  Use the existing dependency-aware installed executor with three bounded workers.
  Surface failed required originals in the producing job before collection.
- Execute large installed probes through small isolated launchers and exact
  readonly payloads, avoiding operating-system argument limits. Independently
  reconstruct payload bytes and preserve original failure and interruption outcomes.
- Install the Source-owned preimport audit before auxiliary execution, including
  portable pipeline and logical-plan children. Retain actual failed-child facts,
  streams and exits even when the child could not write its final report.
- Repair Active's portable documentation links and prepare Advanced's declared
  Meta provider in its Linux auxiliary environment. Lean remains exactly 4.35.0.
- Nominate the actual cold interpreter for native core stages and retain the
  exact environment digest required by native process readback. Clamp stage
  launch deadlines directly to the original deadline.
- Stop native originals after the first retained nonzero or custody refusal.
  Fixed public phase, PID and remaining-time diagnostics expose preparation,
  child completion and terminal observation without granting acceptance.

## Coordinated version and publication

The release-plan command prepares a reviewable exact-input metadata transaction,
including SDK requirements, compatible locks and manuscript publication bindings.
It preserves third-party lock records and exemplar own versions, retains rollback
bytes, and refuses stale plans or foreign edits. It does not publish or grant acceptance.

Focused tests, snapshot validation and static review have separate evidence from
complete hosted runtime, native, coverage, live and release acceptance. Performance
targets are not achieved-speedup claims. The release workflow appends the accepted
commit, hosted run and aggregate receipt hash to these notes, then verifies the
admitted wheel, source distribution, illustration and asset manifest.
