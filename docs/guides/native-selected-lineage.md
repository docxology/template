# Native lineage obligations selected by Source

Native acceptance checks a complete configured Core run and project suite, then
the actual Source manuscript, artifact, control and occurrence contracts. It
retains Original and independently executed Current evidence separately.

The selected lineage projection keeps broad coverage limitations as advisory
DATA. Those descriptions explain the boundaries of registered APIs and project
suites; they are not unconditional release failures for every artifact.
Acceptance instead retains the exact unresolved edges returned by the genuine
Source graph and native adapters.

An authored manuscript copied exactly without generated tokens does not create
hypothetical generated-value obligations. A consumed generated token still needs
its Source key, ordinal, source/output byte ranges, actual completed producer
write and consuming read, independent domain meaning, and native location.
Unknown keys remain specific residuals. Equal formatted numbers do not identify
their producer or native location. Custom generated fragments remain unresolved
until their selected Source algorithm and domain are checked.

The complete native Source asset roster identifies consumed figures. Producing
an unused figure alone creates no consumption obligation. Consumed generated
figures retain their actual path and hash and any missing producer, scientific
domain or native role proof. Source registry, resource, Mermaid, font, layout,
scientific and control failures continue to block their selected artifacts.

The projection creates no process owner or runtime result. Source admission,
Tool/OS results, full Core/Common suites, fresh Current execution, provider and
input custody, actual negative diagnostics, timeout/cancellation and closing
checks remain in their existing Source callers. A status label, declaration or
empty aggregate cannot substitute for those checks. New Source bytes require
new acceptance evidence.
