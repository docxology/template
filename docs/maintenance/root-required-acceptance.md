# Root required acceptance

The source-owned [literal policy](../../infrastructure/config/root-case-policy.json)
binds every collected function, parameter member, source hash and fixture/marker
metadata hash. It retains Python 3.12, 3.13 and 3.14 on Linux and macOS. Only the
two actual Linux `/proc` controls have Linux-only applicability. Missing tools,
prepared local models, public contract fixtures and external datasets block the
applicable required cells. They do not remove those cells.

The prerequisite inventory declares executable names, real public fixture paths,
installed Python distributions and actual provider environment keys. Private
contract controls use tracked public fixtures; private checkouts and credentials
are not prerequisites. External Requests/FastAPI fixture trees and timeseries
data must be prepared before their original controls can pass. Rendering needs
the declared native tools, including a prepared browser for Mermaid. Git clone
revision controls require actual Git 2.51 or newer. The original tests remain
responsible for tool version, daemon, prepared model and rendering behavior.

The six hosted Root jobs install the locked `timeseries-bench` dependency group
alongside `dev` and the explicit `rendering-pptx` group, clone the declared public Requests/FastAPI fixtures through the
existing source-owned fixture helper, and call the existing deterministic
synthetic generator for ten explicitly synthetic time-series fixtures. Synthetic
fixtures are not described as downloaded M4 data. No literal case is removed.
Model daemon/model acquisition requires separate user approval; the workflow
keeps automatic test model pulls disabled and missing models block admission.

The native job also installs `rendering-pptx` explicitly, preserving source
default groups. Its [browser dependency preparer](../../infrastructure/reporting/native_dependency_preparation.py)
reads the exact MathJax 4.0.0 and NewCM font 4.0.0 registry URLs and SHA-512
integrities from the source lock. Finite original download processes and original
archives are retained under `output/readiness/native-dependencies`; the existing
CDN inspector independently checks their package closure. These bytes certify
the pinned offline source assets, not CDN availability. Library version output
is not substituted for the native producer's before/after decoder-byte custody.

The hosted Ubuntu native job prepares LibreOffice, Calibre, Java and ZBar from
the runner's authenticated Ubuntu package repositories, then executes their
actual version commands. See the official [Calibre package inventory](https://packages.ubuntu.com/noble/calibre).
The separate [EPUBCheck preparer](../../scripts/shell/prepare_native_epubcheck.py)
uses the official [W3C EPUBCheck 5.4.0 release](https://github.com/w3c/epubcheck/releases/tag/v5.4.0),
exact 33,093,170-byte archive and pinned SHA-256. It rejects unsafe/duplicate ZIP
members and expanded archives over 64 MiB before extracting into a fresh runner
scratch directory. The native observer receives the actual bundle JAR and
resolved Java runtime `bin/java` paths, retaining its independent engine custody
and original rendering/reader checks. Preparation success does not certify any
native format; the complete original observer still determines those outcomes.

The v3 policy retains the exact authenticated Monid production catalog case in
its full census as `optional-external`, visibly unexecuted and uncertified.
Deterministic local SDK, authentication, request, parsing and error controls
remain mandatory. Only this literal family may use the optional classification;
other obligations cannot be waived through this protocol. Mandatory runtime
selection excludes its production request while full source coverage and original
collection retain the case. An API key does not authorize its execution.

The [official API](https://monid.ai/docs/api/discover) requires an API key for
`POST /v1/discover`; the [pricing documentation](https://monid.ai/docs/guide/pricing)
describes execution prices without establishing a free discovery contract. The
retained review records billing `unverified`, exact provider/operation and
`MONID_API_KEY`. It is historical visibility rather than execution authority;
separate authorization and verified eligibility are needed for a production call.
Legacy mandatory `live-unverified` cases remain permanently blocked by
`unpaid-operation-eligibility-unverified` even when a key is supplied.

The original census producer emits a lossless canonical JSON DAG in a bounded
canonical zlib/base64 envelope. Readback rejects oversized, truncated, corrupt or
trailing streams and verifies exact original DAG size/hash and re-encoding. Deduplication
retains every original observation, literal member, original pytest exit code,
process and interpreter custody. Independent readback expands the authenticated
representation before applying the existing strict original validators. Altered,
cyclic, forward, ambiguous or unused observations are refused. The 64 MiB archive
and expanded observation ceilings remain unchanged.

The [dedicated workflow](../../.github/workflows/platform-required-acceptance.yml)
collects six original Root audits, all 25 native formats, and all project, installed/export and remaining
source-owned obligations. Each literal Root cell has a fixed host/minor owner;
Linux 3.14 owns policy and combined Root branch coverage. A blocked owner remains
blocked even if another audit reports pass. No duplicate gate chooses a winner.
Every six-target original audit must retain its complete inventory. Linux owns
common auxiliary gates; Darwin 3.14 owns both actual macOS gates. The actual
transfer receipt has its own fixed producer. Full original blocked audits remain
bound to the aggregate; ownership never chooses outcomes by status.

Hosted Root readback uses a separate versioned portable observation contract.
Original workers observe physical Root identity, exact interpreter and packages,
loaded SDK custody, and every selected runtime provider file before and after
actual cases. No executable distribution is copied. The collector independently
retrieves all six fixed artifact IDs through the official API, verifies exact
repository/run/SHA/workflow/archive digests, and admits each confined member's
actual bytes. The candidate header binds this original origin manifest.

An external exact-SHA handoff supplies a typed expected context. The portable
reader refuses without it, authenticates the complete original evidence closure
against one fixed host/minor artifact, and reconstructs every original command,
census, policy unit, setup/call/teardown outcome, finite timeline and coverage arc
against current source. It does not reopen an original host's filesystem. Legacy
local readback retains its existing physical identity and selected runtime checks.
Only repeated immutable archive origin authentication is cached inside one reader;
all logical source/case/coverage checks remain independent and each fresh reader
reconstructs origin authentication again.

Sandbox transfer uploads only an independently admitted current Root export with
one-day retention, downloads that exact artifact ID, and verifies actual API
repository/run/SHA metadata and retrieved ZIP bytes. It uses existing read-only
contents/actions scope. It neither publishes a release nor acquires credentials.
The final aggregate independently validates the complete candidate profile and
stages only its referenced public evidence. A failed, blocked or unknown candidate
produces an audit and cannot upload `platform-required-acceptance`. A passed
bundle includes `output/readiness/release-candidate/receipt.json` with exact
`source_commit`; the release workflow independently verifies the successful
same-repository exact-SHA run, artifact and receipt digest again.

After integrating source changes, regenerate the original complete census and
review/update every changed literal family/member/source/metadata binding.
Recollect once more against the installed final policy before collecting runtime
acceptance. Earlier census bytes cannot be rewritten into fresh execution proof.
