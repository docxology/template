# Source-owned Root case acceptance

Root schema 2 requires an explicit reviewed family policy and prerequisite file
under `infrastructure/config/`. Every family has literal parameter members,
source and inherited marker/fixture metadata hashes, a lane and declared
obligations. No unmarked family defaults to core. The original full collection
must match that reviewed policy before any case executes.

`RuntimeScope.require_case_units` exposes declarations only. It grants no case
execution, exclusion or provider authority. The canonical Root acceptance CLI
uses `--mode core|live`, defaulting to core, and prepared `--python MINOR=PATH`
interpreters. It never acquires dependencies or runtimes.

For each prepared supported interpreter, a source-audited coordinator collects
once and executes the complete units applicable to its actual host and selected
mode. A finite outer guardian covers worker startup, admission, collection,
unit execution, original readback and reporting. Its remaining budget bounds
all nested guardians; case deadlines remain separately enforced. The public API
also measures synchronous caller admission and refuses launch when that budget
is exhausted. An enclosing program must supervise synchronous API admission and
final receipt writes if it requires a hard deadline for the entire multi-runtime
program. The CLI `--timeout` is the finite per-interpreter cohort allowance.

Original child exit codes remain in native artifacts. An executed incomplete
case process with original 0, 2 or 7 fails acceptance. Interruption 130 precedes
timeout 124, then failure 1, required unavailable work 75 and complete 0.
Invalid invocation is 2 before execution. The coordinator and independent reader
require the exact original full case inventory, every setup/call/teardown phase,
zero unexpected skips or deselections, unchanged source and bytecode custody,
exact selected installed-runtime identity and complete current evidence.

The independently selected reader runs in the original prepared interpreter.
A Python 3.14 parent cannot reconstruct a Python 3.15 receipt using its own
installed dependencies. The reader authenticates original processes, commands,
source policy, source/deliverable identities, exact case membership, finite
timelines and coverage arcs. Original roots and evidence are confined with
held-directory identity and canonical atomic writes; replacement roots and
symlink targets cannot redirect publication evidence.

Required cells come from all source-owned units, Python 3.14 and 3.15 and
Darwin/Linux applicability. Explicit source-owned platform obligations may narrow
a unit's applicability; missing tools, providers or hardware cannot. Other hosts,
missing prepared interpreters and live work excluded by core mode remain visible
as blocked required cells. A locally complete core cohort can therefore produce
an operational zero while the program returns 75 for missing required release
cells. Current-host readback authenticates its original physical root; transporting
and admitting another host's original evidence is a separate required boundary,
not an absolute-path rewrite or parent-runtime waiver.

`required_profile` and readiness derive the exact case gates from source policy,
not from a receipt's reported allowlist. Schema-2 coverage must be reconstructed
from the original passing units' branch arcs and still satisfy the public source
scope and 60% floor. Private-contract units cannot contribute to public coverage.
Public generic private-provider contract checks do not establish private research
correctness or authorize exposing private origins.

Network markers alone never authorize credentials or an unpaid operation.
Source-owned prerequisite admission additionally binds provider, operation,
unpaid eligibility and fresh primary documentation. Missing tools, keys or
eligibility remain blocked; paid execution is outside this program. Publication,
installed-wheel acceptance, rendering, domain acceptance, hosted CI and exact
remote release evidence remain separate requirements.

The genuine controls in `tests/infra_tests/project/test_root_runtime_v2.py` use a
small source-owned Root fixture. They prove this bounded execution contract and
its negative controls; they do not substitute for the consolidated production
Root collection, literal reviewed classifications, all target environments or
any exemplar's own acceptance.

The existing designated Darwin `root:macos:rendering` auxiliary observation
also retains complete Storybook and Newspaper print witnesses. Every source
page is included at 150 dpi, alongside original before/after complete source
SDK, interpreter, installed decoder RECORD and selected font observations.
Readers validate the retained native PDF/source image or glyph projections
without opening original producer font, library or executable paths. Exact
raster bindings include every page in the unchanged 64 MiB hosted closure.
These component observations require the enclosing genuine auxiliary child
and existing same-run/source-SHA artifact origin. They do not replace full
Root execution, project domain/source admission or required native format
acceptance. Image print documents use the existing bounded 250 MiB expanded
raster-document budget; encoded PDFs remain bounded to 64 MiB and retain the
original page, geometry, pixel and deadline checks.
