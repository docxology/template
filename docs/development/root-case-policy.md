# Root case policies

The platform declares policy version 3 and its prerequisites in
[`pyproject.toml`](../../pyproject.toml). Its complete literal policy uses
[`root-case-policy.json`](../../infrastructure/config/root-case-policy.json)
and the derived source parts. Declaration and policy admission require this exact
current version. Runtime, census and plan record versions remain independent
contracts.

Root runtime acceptance requires a fresh complete case inventory and independently
reviewed classification before execution. Source changes to test modules or public
fixtures require genuine collection, reviewed policy renewal and recollection.
The policy, observer, canonical census producer and independent census reader
are separate contracts; exact lane execution and required readiness wiring remain
mandatory. A compiled plan grants no acceptance and cannot authorize publication.

`infrastructure.project.public_acceptance_case_policy.RootCasePolicy.parse` admits
only the versioned explicit families, exact parameter IDs, required obligations,
Python 3.14/3.15 and Linux/macOS targets. No wildcard, implicit unmarked-case lane,
waived requirement, extra field or optional obligation is supported. Classification
uses the complete authenticated census: missing, added, duplicated or changed
cases, markers, public fixture sources, source bytes and parameter IDs refuse it.

`RootCaseObserver` observes real pytest collection hooks, module/class/function
marker inheritance and resolved fixture definition origins. It never invokes a
case or fixture. Empty, partial, filtered, skipped, erroneous, executed or
source-mutated collection refuses census creation. Public source origins use
confined snapshots. Nonpublic origins are generic inadmissible records; marker
strings/object representations cannot disclose runtime paths or credentials.
Runtime provider source hashes remain in the observation and require independent
selected-provider custody. Their bytes do not enter the cross-runtime policy
metadata digest; each environment must prove its own actual provider bytes.

Primary lanes are core, live-unpaid, private-contract, external-fixture and
offline-benchmark. Markers impose obligations; they never grant credentials,
provider billing eligibility or a passing skip. A network obligation requires a
specific provider/operation, billing `unpaid`, and a reviewed public source
reference with its SHA-256. The independent reader must authenticate the reference
and the operation's actual eligibility. A missing credential or required tool is
blocked. Paid operations are outside this program. Private implementations supply
separate contract receipts and cannot contribute public source coverage.

The classifier expects an independently authenticated full census. The producer
and reader must bind exact original specifications, process results, full source
and configuration identity, selected interpreter, providers and audited bytecode.
A JSON-shaped census alone proves none of these. Lane execution must preserve
original child exits and all setup/call/teardown outcomes; unexpected skips or
incomplete execution cannot pass. Full readiness requires every applicable lane,
capability and target, with current evidence and the declared coverage floor.

The proposed controls in `tests/infra_tests/project/test_root_case_policy.py`
collect genuine tiny owned source in fresh audited children. Marker files prove
that fixture/case bodies were not called. Actual import errors, collection skips,
zero collection, filtering and post-collection source mutation refuse a census.
Strict parser/classifier negatives cover inventory, identities, undeclared marks,
nonpublic origins, target waivers and missing or paid operation eligibility.
These are focused contract controls, not complete Root acceptance.

Canonical collection uses the selected installed interpreter and its actual SDK
provider. It neither installs dependencies nor executes test or fixture bodies.
The public command is:

```sh
.venv/bin/python -m infrastructure.project.public_root_case_census --root . \
  --directory "$PWD/output/readiness/root-census-fresh" --timeout-seconds 660
```

The evidence directory must be fresh, confined and ignored. A native guardian
covers coordinator admission, full-file collection, source/provider verification
and immediate readback. The inner record preserves the original pytest process
exit independently of the outer coordinator outcome. Interruption and timeout
remain 130 and 124; a child exit zero without the required receipt fails.

`public_root_case_readback.read_root_census` takes the exact returned artifact
bundle and separately reviewed complete `RootCasePolicy` under its enclosing
readiness/program worker deadline. Policy admission must load this baseline from
confined source-owned declarations. The initial producer validates a collection
candidate; it grants no classified acceptance before that policy comparison.
The public reader reconstructs
both original commands, the full Root file selection, source and physical Root
identity, selected runtime and SDK custody, public and runtime fixture origins,
inherited markers, complete parameter members, and the original workers' fresh
audited bytecode. A plain independent reader freshly verifies its own loaded
source baseline and compares all source, distribution and selected-runtime planes
exactly. Its reader-context bytecode label differs from the original worker label;
this cannot authorize a worker without an actual fresh audited launcher. It
rejects extra fields, changed sources, rehashed wrong-run metadata, collection
skips, filtered or executed collections, and incomplete native process records.
Collection evidence has role `canonical-collection-only`; it is not a runtime,
coverage, live capability, publication or release receipt.

The focused census controls use actual isolated collection processes. Native
exits 0, 2 and 7 without a receipt cannot pass. A real detached descendant publishes
its own PID/startup record; a concurrent native observation proves it is alive
before timeout, then absence or a non-executable zombie proves guardian cleanup. Readback controls
rehash altered original records consistently and still require source, provider,
identity, completeness and process semantics. Tiny owned Root controls prove
these contracts without supplying the production inventory or its obligations.

The plain-reader control invokes an actual isolated selected interpreter without a
fresh bytecode prefix, admits the actual SDK provider, and reads the original
successful bundle. The same process is refused as a census worker. Consistently
rehashed baseline/unknown original bytecode labels and changed implementation
runtime/distribution records still fail readback. This reader API compares evidence
inside its caller's finite guardian; it does not claim new collection or reader
launch freshness merely from source hashes.

The independent reader shares one freshly verified specification observation
between its original inner and outer process checks. This removes a duplicate
full implementation capture within the same readback boundary. Every distinct
coordinator and collection worker admission and post-collection custody check
remains. A real profiler observes the original capture function executing once;
no implementation or provider is replaced. This optimization does not establish
a timing guarantee under varying host contention.

The detached collection control uses a finite 120-second whole allowance after
an observed successful cold fixture required 109.96 seconds under measured host
contention and the prior 30-second control did not reach the import. Its 300-second
descendant and 360-second import waits exceed that allowance. Original 124,
actual import, owned live PID/token and subsequent native absence/zombie remain
required; a prelaunch timeout fails the control. Production deadlines are unchanged.
This measured fixture allowance does not establish a universal timing guarantee.


The source policy may use the lossless `template-root-policy-encoding-v1`
manifest and derived `root-case-policy.part-0000.json` files in
`infrastructure/config/`. `public_root_policy_encoding.encode_policy` retains
every explicit family, parameter member, lane, obligation and source/metadata
hash in canonical JSON. It changes serialization only; classification and
current full-census admission remain mandatory. The retained policy draft
requires fresh collection and review after source changes.

The loader authenticates ordered part sizes and SHA-256 values before bounded
reads, then authenticates the complete decoded bytes and logical policy digest.
It refuses missing, linked, reordered, changed or noncanonical parts, duplicate
JSON fields, oversized expansion, trailing data and incomplete original policy.
Parts have a 512 KiB file ceiling, the manifest has a 16 KiB ceiling and expanded
policy retains the existing 64 MiB ceiling. Part filenames derive exclusively
from the source configuration path; the manifest cannot select external files.
Serialization grants neither an execution waiver nor freshness for a retained
census. Reviewed authoring still covers every actual family and obligation.
