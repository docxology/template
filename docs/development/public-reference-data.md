# Complete public source DATA references

The installed platform wheel supplies executable infrastructure. A wheel does not supply the Root tests, manuscripts, complete exemplar roster or native Git facts used by Pitch and TemplateTemplate. Those are a separate explicit source DATA input. Never add the reference Root to `sys.path`, manufacture checkout files beside a wheel, substitute a partial scaffold, or drop the whole-source cases.

`admit_public_reference(root, expected_commit=..., expected_source_identity=..., deadline=...)` admits the actual native Git Root against a full commit and canonical `RuntimeScope(root, 'root').source_identity()` fingerprint supplied by the trusted preparation harness. Production expected values must come from the admitted candidate binding. Computing a fingerprint inside a dirty reference and declaring it approved is not admission. A prepared source archive without a source-bound tracked inventory remains unsupported.

The contract reuses the current source fingerprint, public roster, source exclusions, stable deliverable inventory, SnapshotReader and actual implementation custody. Source and stable deliverable bytes must be regular confined files, exist in the exact HEAD/index tree, agree with committed raw Git blob identities and modes, and match the supplied fingerprint. Native tree metadata also applies the existing source-owned project/resource allowlists, preserving legitimate navigation docs while refusing private lifecycle/resource paths and credential/control filenames before any corresponding content read. Native Git runs fixed read-only builtins with no replacement objects, external filters, ambient Git environment or lazy fetching. Effective local/worktree/include promisor configuration is explicitly refused before object traversal, with ambient global/system configuration cleared. Skip-worktree, assume-unchanged, unresolved stages and symlinks refuse admission. The genuine Root gitlink at `infrastructure/steganography/kmyth` is admitted only against its actual committed `.gitmodules` path/URL declaration and Root HEAD/index pin. Only the actual declared path/URL and inert optional branch field are supported. The URL/branch remain committed DATA; no routing, initialization, fetch or update command uses them. Its already initialized native checkout must have that exact HEAD and index; every consumed nested byte must match its actual raw committed blob and mode. Native nested inventory is rechecked at completion. Unknown or recursive submodules are unsupported, and the helper never initializes, fetches or updates a submodule. Missing pinned checkouts block the lane. Every canonical public project needs its nonempty source, tests, scripts and actual manuscript scope. Unsupported or missing references block the applicable source-data lane; they do not permit skips or an adjusted coverage floor.

The source identity covers the existing canonical public source and stable deliverable policy, rather than local navigation or runtime files. Full native HEAD/index metadata is separately bound by the commit. Nested `.git` control files/directories are excluded from canonical readiness source metadata; genuine nested commit and index custody are separately retained. Checkout-control locations are not source DATA. This changes the canonical fingerprint for initialized submodule checkouts; all fresh candidate profiles must bind the revised digest. Canonical source/byte inventory remains bounded to 100,000 entries and 512 MiB held bytes; each SnapshotReader file retains its existing 64 MiB limit. Private/control filenames and symlink paths are admitted before inventory hashing through an optional path-policy callback. That callback does not change ordinary fingerprint serialization or default scope.

The selected actual SDK retains its source-checkout or genuine installed METADATA/RECORD custody. Every infrastructure Python file in the DATA reference must equal its current selected SDK counterpart, and both actual identities must match the declared current platform version. Same version text alone cannot establish this equality. Installed acceptance must still use its real admitted wheel and fresh interpreter outside forbidden source import roots.

`PublicReference.read(relative)` returns already captured immutable bytes. Existing Path consumers can use the read-only `PublicReference.root` while their caller retains the reference and requires `verify_unchanged(deadline=...)` before accepting results. This final check covers physical Root replacement, every captured file identity, directory inventory mutations including restored edits, whole source/deliverable fingerprint, committed/index inventory and actual SDK recapture. A Path consumer must not use excluded runtime/private files as research inputs; a new consumed input belongs in its declared admitted scope. Creating bytecode or outputs in the reference is incompatible with a read-only DATA lane; use an independently selected SDK and disposable own-project output tree.

Native commands share the original remaining finite clock. The existing synchronous tree/custody APIs and subprocess output capture are not filesystem/resource sandboxes; a source-audited supervised caller supplies a hard whole-operation bound. This helper performs no installs, network retrieval, model execution or publication.

The three explicit environment fields `TEMPLATE_PUBLIC_REFERENCE_ROOT`, `TEMPLATE_PUBLIC_REFERENCE_COMMIT` and `TEMPLATE_PUBLIC_REFERENCE_FINGERPRINT` are admitted together by `reference_binding`. No supplied fields means no DATA binding; a partial binding is invalid. This is a preparation contract, not proof inferred from an ambient sibling directory. Own-project integration must retain final source-data verification and all existing numerical/domain/format controls.

The proposed Root controls copy real complete canonical public source and stable deliverables, preserve empty directories and the actual pinned submodule via a local-only clone of its existing native checkout, create an actual owned native Git commit, and use that harness binding. They retain genuine SDK identity and prove data-shadow code executes in an ordinary owned child before guarded refusal. Actual nested pin/blob/index/missing-checkout controls, index flags, partial roster, raw source additions/deletions/renames/tampering, restored edits, physical Root replacement, wrong external identities, unsupported archives and a live private-filename-open audit control must refuse. Fixture commits are explicit owned controls; they are not the production candidate or installed-wheel acceptance. After source review/application, run these real controls and separately run both full own suites against the admitted clean candidate outside their source checkouts.
