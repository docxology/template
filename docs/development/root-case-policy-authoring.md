# Authoring the complete Root case policy

First apply the independently reviewed source batches and collect the actual full
Root using the canonical audited selected interpreter. Retain the original native
coordinator, collection process, census receipt and source identity. Collection
alone is a candidate, not classified runtime acceptance.

`family_ledger` reads the original collection candidate and emits every module,
family and parameter member. It refuses modules outside the actual public Git
tracked test inventory. It uses the reviewed fixed native Git builtin with clean repository/index/config routing and refuses concurrent public-index changes. Parents must admit newly reviewed public files to the
index before the final census/authoring step; the authoring helper never stages
or changes source and never reads private mirrors.

Review every module's source and its actual inherited markers, fixtures and
skip conditions. Record an explicit module decision with the exact family list,
module source hash, source-hashed public line references and explicit family
exceptions. No unmarked family defaults to core. Review data is a draft input;
record presence and matching source lines do not prove a correct classification
or that independent review occurred.

`author_policy` requires an exhaustive decision for every observed module,
refuses omissions, invented/duplicate exceptions, stale source or evidence,
and emits literal rows for every original family/member/source/metadata hash.
The existing strict policy compiler enforces all marker and assigned-obligation
requirements, including offline core's refusal of opt-in obligations. The helper
then authenticates the original outer coordinator through the canonical census
reader with that complete draft baseline. It writes no policy and executes no
cases or provider operation.

Provider/operation eligibility needs explicit primary documentation, unpaid
billing classification and fresh source-owned prerequisite bindings. A network
marker cannot supply this authority. Paid execution remains excluded. Ambiguous
provider, private/external fixture, tool, platform and side-effect groups need
fresh independent source review; generic public private-provider contracts may
not contain private names/paths/content or count as private research acceptance.

After independent review, install the complete literal policy/prerequisites and
source declaration in one parent-owned change, then recollect the actual Root.
The original authoring census remains historical evidence because installing the
new source files changes source identity. Only the new exact-source census,
source-owned policy admission, real execution and independent original-reader
receipts can close runtime or release requirements. Every supported Python minor
and applicable Darwin/Linux unit remains required regardless of tool availability.

The draft author supports an explicit `policy_schema` keyword for v2 or v3,
while keeping v2 as the legacy default. Selecting v3 retains the same complete
census, exhaustive decisions, source evidence and strict optional-operation
parser. It grants no additional exception. The current source declaration and
fresh independent review still determine the installed policy protocol.
