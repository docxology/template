### Major

#### MAJ-1 — Test-suite load fragility: subprocess-heavy tests exceed global 10s pytest-timeout under concurrent load
- **Evidence:**
  - Global timeout: `pyproject.toml:266` (`timeout = 10`, `timeout_method = "thread"`).
  - Full `tests/infra_tests/` run aborted at `tests/infra_tests/autoresearch/test_autoresearch.py:904` (`test_cli_plan_review_summarize_and_benchmark_write_declared_artifacts`) with a raw `subprocess.communicate` selector hang trace rather than a clean pytest-timeout failure.
  - The suite aborted independently in `tests/infra_tests/rendering/test_core.py::test_render_all_tex` and again in `tests/infra_tests/validation/docs/test_doc_pair_lint.py` on separate runs.
  - Every affected test **passes in isolation**: the autoresearch test = "1 passed in 24.17s" standalone (vs the 10s global budget); doc-pair file = "8 passed in 30.44s" standalone.
- **Root cause hypothesis:** these tests spawn real LaTeX/pandoc/CLI subprocesses whose wall time legitimately exceeds the 10s default on a loaded machine (multiple agent sessions + mmdc/chrome processes active here); under contention they blow past `timeout = 10`. Thread-based timeout also appears to leave the subprocess select loop hanging instead of failing fast in some cases, cascading into suite-level aborts.
- **Why Major (not fixed):** changing global/per-test timeouts trades CI hang-protection for local robustness and touches the test-harness concurrency model; it needs cross-machine measurement and a policy decision (per-test explicit `@pytest.mark.timeout(...)` budgets vs raising the global floor vs marking genuinely slow tests `slow`).
- **Scoped plan:**
  1. Measure standalone durations for all subprocess-spawning infra tests (`--durations=50` on a quiet machine).
  2. Give every test that legitimately runs real LaTeX/pandoc/mmdc subprocesses an explicit `@pytest.mark.timeout(N)` sized ≥3× its measured p95 (autoresearch CLI ≈30–60s; render_all_tex ≈60–120s; doc-pair file ≈45s).
  3. Consider `timeout_method = "signal"` on POSIX CI runners so overruns fail cleanly instead of hanging in `select()`.
  4. Acceptance criteria: full `pytest tests/infra_tests/ -p no:cacheprovider --no-cov` completes with exit 0 on a quiet machine AND survives a synthetic-load rerun without cascade aborts; negative control: an artificially sleeping test must still be killed at its declared budget.
  - Effort estimate: 0.5–1 day. Risks: longer wall-clock CI; masking genuine hangs if budgets are too generous — keep the negative control mandatory.
